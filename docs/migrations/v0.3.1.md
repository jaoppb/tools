# Migrating from v0.3.0 to v0.3.1

Previous: [v0.2.0 → v0.3.0](v0.3.0.md) · Next: none yet

`v0.3.1` is a patch release of the v0.3 line, cut from the `release/v0.3` maintenance branch: `v0.3.0` plus two fixes. The binary, the composite action inputs and `tools.toml` are unchanged, so nothing has to be migrated; this guide lists what you can now drop or rely on. Where a later release changes something again, the section ends with a **Later** note.

## Summary

| Change | Issue | Action needed |
|--------|-------|---------------|
| [The Nix package builds in the sandbox](#the-nix-package-builds-in-the-sandbox-117) | #117 | Optional: drop your `nativeCheckInputs` workaround |
| [Release-note links point at the tag](#release-note-links-point-at-the-tag-107) | #107 | None |

To move to this release, pin both the action and the binary:

```yaml
# Before
- uses: jaoppb/tools@v0.3.0
  with:
    version: v0.3.0

# After
- uses: jaoppb/tools@v0.3.1
  with:
    version: v0.3.1
```

For a flake input, point it at `github:jaoppb/tools/v0.3.1`.

## The Nix package builds in the sandbox (#117)

**What changed.** The flake package declares `git` as a check input, so its check phase no longer fails in the Nix sandbox (`git runs: NotFound`). `nix flake check` now builds and tests the package too.

**What you must do.** Nothing. If you consume the flake and added `git` to the package's `nativeCheckInputs` (for example through `overrideAttrs`) to work around the failure, you can remove it:

```nix
# Before
tools = inputs.tools.packages.${system}.default.overrideAttrs (old: {
  nativeCheckInputs = (old.nativeCheckInputs or [ ]) ++ [ pkgs.git ];
});

# After
tools = inputs.tools.packages.${system}.default;
```

The binary still calls `git` at runtime without bringing it along (#130), so the environment that runs `tools` must provide `git` on `PATH`.

## Release-note links point at the tag (#107)

**What changed.** The GitHub release notes rewrite relative CHANGELOG links, such as the migration guide link, to `https://github.com/jaoppb/tools/blob/<tag>/<path>`. Before, a release page resolved them under `/releases/tag/` and they returned 404.

**What you must do.** Nothing.
